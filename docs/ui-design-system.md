# OFFICESTRA 공통 게임 카드 디자인

사용자가 승인한 직원 선택 카드의 입체감과 모델색을 공통 기준으로 사용한다.
구현은 `Sources/OfficeGame/OfficeGameDesign.swift`에 모은다.

## 두 테마

- 다크: 짙은 바탕, 모델색 조명, 밝은 글자, 얇은 금속성 테두리.
- 라이트: 밝은 유리·메탈 바탕, 은은한 모델색, 짙은 글자. 검정 카드를 그대로 옮기지 않는다.
- `.white` 글자나 다크 배경을 화면마다 고정하지 않는다. `OfficeGamePalette`와 현재 `colorScheme`을 사용한다.
- 모델색은 `DashboardPalette.providerAccent(for:)`로 얻는다. 직원별 장식색과 혼용하지 않는다.

## 공통 컴포넌트

```swift
// 현재 직원, 중요한 선택 카드. 가장 강한 장식 단계.
.buttonStyle(OfficeGameButtonStyle(accent: modelColor, emphasis: .hero))

// 일반 도구 버튼과 탭. 라벨에서 크기를 지정한다.
.buttonStyle(OfficeGameButtonStyle(isSelected: selected, cornerRadius: 10))

// 정보·본문 패널. 글자색과 내부 레이아웃을 덮어쓰지 않는다.
.officeGameSurface(accent: modelColor, cornerRadius: 14)
```

`hero`는 직원/핵심 선택, `control`은 버튼/탭, `panel`은 큰 정보 표면에 사용한다.
`transcript`는 코덱스 대화·작업 기록의 녹색을 유지하는 표면이다. 일반 패널의 낮은 채도로 대체하지 않는다.
작은 도구 스타일은 호출부의 모델색·상태색 글자를 중립색으로 덮어쓰지 않는다.
본문·코드·표·터미널에 강한 면광이나 장식 테두리를 반복하지 않는다.
시스템 메뉴·폼·경고창은 네이티브 동작과 키보드 접근성을 유지한다.

## 모션과 상태

- 공통 카드 효과는 hover/press 때만 짧게 움직인다. 상시 타이머, 반복 SwiftUI 애니메이션, 화면 전체 blur를 추가하지 않는다.
- Reduce Motion이면 크기와 전환 애니메이션을 끈다. disabled, 선택됨, 오류 상태를 장식으로 가리지 않는다.
- 로딩 보호, 직원 선택, 분할 포커스, 자동 전달, 음성 실행 로직은 스타일과 분리한다.
- 작업 상태는 왼쪽 오피스 말풍선의 점/느낌표를 유지한다. 우측 상단에 직원 얼굴 줄을 복구하지 않는다.

## 현재 적용 위치

직원 선택 버튼/카드 팝오버, 하단 정보 탐색 탭, 사용량 카드, 공통 오피스 패널,
업무 보드 공통 표면/상단 액션, 자동 전달 버튼/팝오버, 음성 지원, 분할 버튼.
그 외 기존 개별 화면을 손볼 때도 새 사설 스타일을 복제하지 말고 이 컴포넌트를 사용한다.

대화창 확장: 질문/응답 카드, 추론·작업 기록, 보관함 카드, 입력창과 첨부/보내기/중단/예약,
모델·추론·권한 설정 라벨, 프로필/설정, 테마/2D·3D/GUI·터미널 전환, 코드 복사,
메시지 평가/복사, 근거, 비용, 위키·업무 보드 도구에도 같은 표면을 사용한다.
앱과 별도 프로젝트 창의 기본 버튼 스타일도 공통 스타일로 지정한다.

반복되는 작은 도구는 `.officeGameTool()`을 사용한다. 별도 그림자나 여백을 추가하지 않아
스크롤 중인 긴 대화와 좁은 하단 설정 줄의 부담을 줄인다. 오류/중단/평가 등 의미 있는 색은 유지한다.
네이티브 메뉴·폼·시스템 경고의 표준 컨트롤과 특수 아바타/포커스 애니메이션은 역할을 유지한다.
터미널과 GUI는 같은 헤더·입력창·설정·분할 프레임을 사용한다. CLI 출력과 구문 강조 코드의
어두운 캔버스는 ANSI/문법 색 대비를 위해 유지하고, 주변 도구와 표면은 오피스 테마를 따른다.

## 검증

다크와 라이트에서 기본/선택/호버/비활성 상태, 이름과 숫자 가독성, 작은 창과 분할 모드의 배치를 확인한다.
`OfficeGamePaletteTests`는 세 모델색과 테마별 본문/보조 글자의 대비를 검사한다.
색상 테스트는 실제 화면 확인을 대신하지 않는다.
